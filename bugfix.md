# Bugfix Log

## Open

- None currently tracked.

## Fixed

- Fixed native math being disabled in correctly packaged macOS apps that embed SwiftMath resources under `Contents/Resources`. The SwiftMath entry guard now accepts both the generated root lookup path and the normal app resource directory before falling back to text rendering when neither resource location exists.
- Fixed release/product scripts running visual RenderProbe checks by default. `Tools/release-check.sh` and `Tools/product-check.sh` now skip PNG/AppKit visual probes unless `SIRIUS_MARKDOWN_RUN_VISUAL_PROBES=1` is set explicitly, while a Swift test guards that opt-in default.
- Fixed public docs overclaiming default visual-probe coverage after RenderProbe was made opt-in. README, DocC, and architecture docs now describe the nonvisual default gate separately from the explicit `SIRIUS_MARKDOWN_RUN_VISUAL_PROBES=1` AppKit probe path, and a Swift test guards the wording.
- Fixed opt-in RenderProbe artifact generation ordering its host window on screen. The probe now renders through an offscreen AppKit host while still writing/measuring PNG artifacts, and the opt-in gate test rejects reintroducing visible window-ordering calls.
- Fixed macOS demo app bundles omitting SwiftPM resource bundles. `Examples/scripts/bundle-macos-demos.sh` now copies built `.bundle` resources such as `SiriusMarkdown_SiriusMarkdownSwiftUI.bundle` and `SwiftMath_SwiftMath.bundle` into each `.app/Contents/Resources`, so packaged demos retain HighlightJS, Mermaid, and SwiftMath font resources.
- Fixed direct empty appends to `MarkdownSourceBuffer` creating empty chunks. Empty appends now return a zero-length source range without mutating chunk storage or offsets, keeping the public source buffer append-only without accumulating useless chunk metadata.
- Fixed prepared native-line view state reuse for same-text semantic changes. `PreparedInlineTextView` now invalidates width-dependent layout state when the measured prepared content or font profile cache identity changes, so a fixed-width host cannot keep stale line breaks when the same visible text changes from plain to code/math/styled measurement.
- Fixed Mermaid render preparation caching on `MarkdownTheme.hashValue`. Mermaid cache keys now use a deterministic renderer-theme identity built from render-relevant theme metrics, font profiles, syntax palette, and affordance settings, so theme-dependent diagram output cannot reuse stale cached renders.
- Fixed custom Mermaid renderers being able to feed invalid geometry into the diagram viewport. The SwiftUI view now accepts only finite positive prepared geometry before using fit/zoom frame math, falling back to bounded scroll behavior for malformed custom renderer output.
- Fixed Pretext golden tooling silently mishandling layout fixture metadata. The JS oracle now resolves fixture URLs through `fileURLToPath` for paths containing spaces, fails missing/non-finite expected scalar values instead of letting `NaN` comparisons pass, requires positive finite width/line-height metadata, and round-trips validated `letterSpacing` while Swift-side fixture coverage rejects nonzero letter spacing until native layout supports it.
- Fixed duplicate caller-supplied host-boundary IDs producing duplicate prepared render-item IDs. Prepared snapshots now keep normal item IDs unchanged when unique and disambiguate colliding render IDs, so SwiftUI `ForEach` receives stable unique IDs even when host-native insertions reuse a boundary ID.
- Fixed nearest source reveal dropping end-of-document cursor positions. `MarkdownSourceRevealPolicy.nearestRenderedBlock` now resolves trailing line and byte-offset gaps at EOF to the preceding rendered block, matching the public DocC contract while `exactOnly` still returns no target.
- Fixed plain-text copy fallback widening partial source selections on public/manual blocks without inline runs. The no-provider copy path now slices fallback block, list-item, and table-cell text by the owning source range instead of returning the entire fallback text whenever inline runs are absent.
- Fixed host-heavy snapshot assembly doing repeated front removals while interleaving native insertion boundaries. Snapshot item construction now consumes sorted host boundaries with an index cursor, preserving order without shifting the boundary array for long host/native transcripts.
- Hardened CoreText inline measurement against impossible attributed-string creation failures. The Core measurer now returns zero width instead of trapping if CoreFoundation refuses to create the attributed string.
- Fixed prepared inline cache keys ignoring run-level source ranges and field boundaries. Both Core inline layout and SwiftUI render preparation now include each run's byte and line source range and hash length-prefixed field values, preventing stale prepared selection/copy geometry when identical visible text is rebuilt with different source ownership or when link text and destination boundaries differ.
- Fixed render-preparation cache namespaces joining host-provided policy, renderer, highlighter, theme, and resolver identities with raw separators. Math, code, Mermaid, and inline preparation namespaces now length-prefix each field, so custom identities cannot alias across adjacent namespace fields and reuse stale prepared output.
- Fixed public named font profiles contributing raw separator-joined values to measurement and render cache identities. `MarkdownFontProfile.cacheKey` and `MarkdownInlineFontProfiles.cacheKey` now length-prefix each public field, so custom font names cannot collide with adjacent cache identity fields.
- Fixed `MarkdownTheme.renderCacheIdentity` and nested theme identities joining values with raw separators. Theme, heading, syntax palette, code-affordance, and Mermaid-affordance identities now length-prefix their fields, preserving Mermaid/render cache separation when public font profile values contain separator-looking text.
- Fixed prepared snapshot reuse treating `isSealed` flips as render-content changes. When a streamed active tail seals without changing its rendered block content or source range, `prepare(snapshot:reusing:)` now reuses the previous prepared content instead of incrementing render preparation work.
- Fixed Mermaid toolbar controls appearing for malformed custom-renderer geometry. The diagram view now requires finite positive renderable geometry before showing zoom/fit/reset controls, matching the viewport path that consumes prepared geometry.
- Fixed image-backed display math blocks publishing no document-selection fragments after preparation. Prepared image math blocks now carry a source-backed selection inline layout and `MarkdownBlockView` publishes fallback text-leaf fragments from that layout, so dragging/copying image-rendered display math selects the original Markdown source instead of dropping the block from selection.
- Fixed prepared inline image display text matching duplicate sourceless image runs by source instead of run order. Manually constructed public `MarkdownInlineRun` images with the same source and no source range now preserve each run's own alt/display text during preparation instead of reusing the first prepared image.
- Fixed selection geometry measuring styled links with plain link metrics. Document-selection font runs now retain `MarkdownInlinePresentation`, so strong/emphasis/code/math presentation is included in CoreText font selection and geometry cache identity.
- Fixed overwide inline layout fallback dropping atomic presentation during cached unit measurement. Preferred-break and grapheme fallback units now preserve code/math/image presentation, keeping fallback measurement consistent with prepared segment semantics.
- Fixed same-offset host boundaries losing append order when interleaved into snapshots. Host-native insertions appended at the same source offset now remain stable in append order instead of depending on an unstable sort tie.
- Fixed public API documentation leaking private incident wording around native text selection. The native-selection comments now describe the macOS host-update risk generically while preserving the bounded-selection guidance.
- Fixed generated LaTeX math recovery still splitting or failing common chat/document formulas. Bare-TeX recovery now keeps score formulas, `\operatorname` / `\operatorname*`, `\mathbb`, `\partial`, `\nabla`, `cases`, `align*`, `equation`, angle-bracket pairs, Greek/font-style commands, relation operators, Unicode subscripts, and alignment separators together as source-backed math runs, while preserving negative guards for code spans, paths, unknown commands, escaped Markdown, and currency-shaped prose. `SiriusMarkdownMath` also normalizes SwiftMath-incompatible generated forms before typesetting without changing the original LaTeX source stored on prepared images.
- Fixed wide code blocks stretching or destabilizing constrained transcript/document columns. Code-block scroll content now keeps natural width inside the horizontal scroll view while the block itself remains bound to the host column, and RenderProbe now asserts overflow fitting width stays contained instead of only checking that wide pixels render.
- Fixed long-generation render-session slowdown where fast streaming appends queued obsolete full snapshot/preparation work and long transcripts could reprepare stable sealed blocks after the bounded render-preparation cache was exceeded. `MarkdownRenderSession` now batches pending operations, coalesces append chunks, drops reset-superseded work before parsing/highlighting, and reuses exact-match prepared block content from the prior prepared snapshot so append-only streaming prepares only changed/new tail blocks.
- Fixed native math rendering in signed packaged apps where SwiftMath's generated `Bundle.module` accessor fatals before SiriusMarkdown can recover. `SiriusMarkdownMath` now guards the generated packaged-app resource path before entering SwiftMath and falls back to text rendering when a consuming `.app` keeps SwiftPM resource bundles under `Contents/Resources`.
- Fixed shipped-app JavaScript resource lookup for bundled HighlightJS and Mermaid runtimes. The highlighter and Mermaid preparation paths no longer depend on `Bundle.module` resolving from the package resource accessor at runtime; they now search the main app bundle, SwiftPM resource bundles, framework bundles, and adjacent resource directories for `highlight.min.js` and `beautiful-mermaid.bundle.js`. This closes the packaged-app crash/fallback class where the resources were present in `SiriusMarkdown_SiriusMarkdownSwiftUI.bundle` but the runtime lookup could still miss them after embedding in a consuming app.
- Fixed default document selection precision across the remaining non-paragraph surfaces. Code blocks, text-rendered math blocks, image-backed inline math, allowed HTML blocks, table cells, list rows, and styled Markdown now publish source-aware selection fragments from prepared layout, while fallback plain-text copy without a source provider respects selected source ranges instead of widening partial selections to whole selected blocks. Cmd-A/context-menu Select All now tracks streamed appends as a full-document intent.
- Fixed UTF-8 source slicing across chunk boundaries. Multi-chunk source slices and line decoding now join byte ranges as one UTF-8 stream before decoding, keeping source-backed selection/copy byte-accurate for multibyte scalars split across append chunks.
- Fixed the default packaged inline renderer still behaving like a compatibility path. `MarkdownRendererConfiguration()`, `.compactChat`, and `.document` now select `coreTextPaintedLines`; AppKit/UIKit views paint prepared line ranges with CoreText, while explicit native text selection keeps using selectable native text leaves.
- Fixed the default `mailto:` link policy accepting percent-encoded query separators inside allowed `subject` values. Destinations such as `mailto:user@example.com?subject=Hello%26bcc=attacker@example.com` and encoded semicolon header separators now deny as malformed instead of allowing downstream mail clients or URL openers to reinterpret the decoded subject as additional headers.
- Fixed display-math inline coalescing leaking across link syntax. A linked literal delimiter such as `[\\[](/docs)` followed by later `\\]` text no longer becomes linked math spanning unrelated lines; the parser now verifies that coalesced `\\[`, `\\]`, `$$`, and degraded bracket delimiters are standalone in the original source line while still allowing block-quote and list prefixes.
- Fixed multiline link labels dropping link context from inline break runs. Soft and hard breaks inside `[label](destination)` now keep the same destination in the public `MarkdownInlineRun` model, SwiftUI attributed rendering links the full multiline label, and prepared-inline cache identity treats destination-bearing break runs as policy-relevant link content.
- Fixed the native Swift code highlighter missing common modern Swift keywords after the JavaScriptCore fallback replacement. Tokens such as `actor`, `throw`, `default`, `final`, `override`, and related declaration/modifier keywords now receive keyword coloring instead of rendering as plain identifiers.
- Fixed native Swift code highlighting for nested string literals inside interpolation. The package-owned Swift highlighter now tracks interpolation bodies with balanced parentheses and nested string/comment scanning, so valid snippets like `"\(String("inner"))"` keep their string content colored instead of dropping the nested literal out of string highlighting.
- Fixed the default Swift code highlighter crashing the render probe inside JavaScriptCore. Swift fences now use a bounded package-owned lexical highlighter instead of Highlight.js/JSC, preserving colored code output and source text while avoiding the native JSC regex crash seen while preparing the overflow probe.
- Fixed image-backed inline math dropping document-selection text-leaf geometry. The native math-image inline path now publishes a source-backed `MarkdownDocumentSelectionFragmentsKey` fallback from the already-prepared inline source range, so default document selection can drag/copy paragraphs containing typeset inline math instead of receiving no selectable fragment.
- Fixed image-backed inline math rendering bypassing configured link actions. The native math-image inline path now installs the same `OpenURLAction` bridge as regular prepared text, so linked inline math routes through a host-supplied `MarkdownLinkAction` instead of falling back to the ambient/default URL opener.
- Fixed image-backed inline math preparation invoking the renderer twice. When `preparedMath` returns a native math image, the SwiftUI preparation path now uses the prepared image's LaTeX source for fallback attributed text instead of calling `renderedMath` again, so expensive math renderers do their image preparation work once while linked math still preserves its destination.
- Fixed source-backed prepared images evaluating image policy twice per run. Render preparation already computes a policy decision before resolving display text, but the prepared display run kept the image source attached and `InlineRunsView` evaluated the same policy again while building the attributed payload. Prepared image display runs now retain image presentation and source ranges for layout/selection while clearing the already-consumed image source, so host policy hooks run once per image preparation.
- Fixed sourceless image-presenting inline runs disabling prepared inline caching when the host image policy had no cache identity. Public `MarkdownInlineRun` values can mark image presentation without a resolved source; those runs render deterministic alt/placeholder text without consulting image policy or resolver, so the inline cache namespace now requires image policy identity only when source-backed image decisions are actually prepared.
- Fixed image-only inline preparation caching incorrectly depending on link policy identity. Standalone image runs carry their image source in `destination`, but rendering and preparation do not evaluate link policy for non-link images, so the inline cache namespace now requires link policy identity only for actual link runs while image policy and resolver identity continue to govern image output.
- Fixed denied inline math output disabling inline preparation caching when a host math renderer had no cache identity. Inline math policy decisions are now computed once during preparation, denied math caches on math policy identity alone, and renderer identity is required only when allowed math will actually render.
- Fixed denied prepared image output disabling inline preparation caching when the host image resolver had no cache identity. Denied image policy decisions now cache on the image policy identity alone because the resolver is never consulted for denied output, while allowed image runs still require resolver identity before prepared inline content can be reused.
- Fixed denied prepared images invoking the image resolver after policy rejection. The SwiftUI preparation path now short-circuits `.deny` image policy decisions into package-owned placeholders instead of calling a host resolver with a denied decision, so the default-safe policy boundary prevents resolver-side fetch or decode work unless the image policy explicitly allows the source.
- Fixed prepared SwiftUI link attributes ignoring policy-normalized destinations. The default policy could allow parser-provided destinations such as `https&#58//example.com/path` and `docs&#47safe` after defensive HTML character-reference decoding, but prepared attributed strings still attached raw `URL(string:)` values like `https&#58//...` and `docs&#47safe`. Link attribution now uses an optional policy normalizer, so rendered/clicked links point at `https://example.com/path` and `docs/safe` while unsafe decoded destinations remain denied.
- Fixed the default link policy accepting HTML character-reference encoded unsafe destinations as relative links. Parser-provided destinations such as `javascript&#58alert`, `file&#58///tmp/secret`, `data&#58text/html...`, and `&#47&#47example.com/path` are now classified through a defensive HTML-decoded policy pass and denied when they resolve to disabled schemes or protocol-relative URLs, while safe encoded `https` and relative slash paths remain allowed.
- Fixed list-contained block constructs sealing before an indented continuation after a blank line. Streamed list items containing fenced code, tilde fences, dollar or bracket display math, raw HTML blocks, or table/reference content now keep the list item mutable until a later indented continuation can be attached, matching one-shot `swift-markdown` instead of splitting the continuation into a separate top-level paragraph.
- Fixed streamed loose list items with continuation lines sealing too early. A list item such as `- First\ncontinued` or `-\tFirst\n\tcontinued` followed by a blank and another item now stays in the mutable tail until the scanner can preserve the whole loose list, matching one-shot `swift-markdown` for both bullet and ordered lists with space or tab marker spacing.
- Fixed the default `mailto:` link policy accepting authority/path-shaped recipients. Destinations such as `mailto://evil@example.com`, `mailto:/user@example.com`, `mailto:user@example.com/evil`, `mailto:%2F%2Fevil@example.com`, and `mailto:user@example.com%2Fevil` now deny as malformed instead of allowing slash-delimited recipient text that Foundation can expose as authority or path structure.
- Fixed tab-delimited loose list items sealing too early during streaming. CommonMark allows a tab after bullet and ordered list markers, but the boundary scanner only treated a literal space as list-like, so streamed `-\tFirst\n\n-\tSecond` and `1.\tFirst\n\n2.\tSecond` split into separate list blocks while one-shot `swift-markdown` produced one loose list. The scanner now keeps tab-delimited list continuations mutable like space-delimited list items.
- Fixed the default `mailto:` link policy accepting percent-encoded recipient-part whitespace and delimiters that Foundation exposes only after decoding. Destinations such as `mailto:user@example.com%20attacker@example.com`, `mailto:user@example.com%3Fbcc=attacker@example.com`, `mailto:user@example.com%3Fsubject=Hi%26bcc=attacker@example.com`, and `mailto:user@example.com%23fragment` now deny as malformed, while encoded spaces in allowed `subject` headers remain allowed.
- Fixed the default HTTP(S) link policy accepting malformed or unusable explicit ports that Foundation still parses. Destinations such as `https://example.com:/path`, `https://example.com:999999999999/path`, and `https://[::1]:999999999999/path` now deny as malformed, while valid explicit ports such as `https://example.com:443/path`, `http://localhost:8080/path`, and `http://[::1]:8080/path` remain allowed.
- Fixed the default HTTP(S) link policy accepting percent-encoded host text that Foundation normalizes before exposing the actionable host. Destinations such as `https://%65xample.com/path`, `https://example%2ecom/path`, `https://example%2Dadmin.com/path`, and `https://%31%32%37.0.0.1/path` now deny as malformed, while percent-encoded path separators such as `https://example.com/a%2Fb` remain allowed.
- Fixed the default `mailto:` link policy accepting unsafe query header fields by default. Destinations such as `mailto:user@example.com?bcc=attacker@example.com`, `?cc=copy@example.com`, `?body=secret`, and arbitrary custom headers now deny unless a host supplies a broader policy, while ordinary `subject` headers remain allowed.
- Fixed the default `mailto:` link policy accepting raw and percent-encoded backslashes. Destinations such as `mailto:user@example.com\evil`, `mailto:user@example.com%5Cevil`, and `mailto:user@example.com?subject=Hi%5Cthere` now deny as malformed instead of letting Foundation normalize or expose decoded backslashes.
- Fixed the default `mailto:` link policy accepting raw whitespace that Foundation silently percent-encodes. Destinations such as `mailto:user@example.com?subject=Hello there` and `mailto:user@example.com attacker@example.com` now deny as malformed, while explicitly percent-encoded spaces such as `subject=Hello%20there` remain allowed.
- Fixed the default HTTP(S) link policy accepting percent-encoded host colons as safe hosts. Destinations such as `https://example.com%3A443/path` and `https://example.com%3Aevil/path` now deny as malformed instead of exposing a decoded `example.com:...` host without a real parsed port, while bracketed IPv6 literals such as `http://[::1]` remain allowed.
- Fixed the default relative-link policy accepting percent-encoded absolute destinations. Inputs such as `javascript%3Aalert(1)`, `file%3A///tmp/secret`, `https%3A//example.com/path`, and `%2F%2Fexample.com/path` are now denied as malformed instead of being classified as safe relative links before platform URL decoding.
- Fixed the default relative-link policy accepting raw and percent-encoded backslashes. Destinations such as `/docs\admin`, `docs\admin`, `/docs%5Cadmin`, and `%5C%5Cexample.com/path` are now denied as malformed instead of being left for platform URL handling to normalize ambiguously.
- Fixed the default relative-link policy accepting malformed percent escapes and percent-encoded control characters. Relative destinations such as `/bad%0apath`, `docs%00path`, `100%`, and `%ZZ` are now denied as malformed while ordinary percent-encoded spaces like `/safe%20path` remain allowed.
- Fixed the default HTTP(S) link policy accepting percent-encoded delimiter smuggling and raw userinfo. Encoded backslashes, decoded host delimiters such as `/` and `@`, and userinfo authorities such as `https://example.com@evil.com` are now denied by default, closing cases where Foundation URL parsing could make the visible destination differ from the actionable host.
- Fixed the default `mailto:` link policy accepting percent-encoded control characters. `mailto:user@example.com%0aBcc:...`, CRLF-injected subject parameters, and encoded NUL suffixes are now denied as malformed destinations while ordinary `mailto:` links and percent-encoded spaces in subjects remain allowed.
- Fixed the default HTTP(S) link policy accepting ambiguous Foundation-normalized destinations. Raw backslashes, percent-encoded control characters, and percent-decoded whitespace/control characters in hosts are now denied by default, so inputs such as `https://example.com\@evil.com`, `https://exa%20mple.com`, and `https://example.com/%0a` cannot pass as safe external links while ordinary percent-encoded path spaces remain allowed.
- Hardened the release gate for reference-definition destination and title parsing. A new generated stream-vs-one-shot matrix now covers nested/escaped parenthesis destinations, escaped angle-bracket destinations, escaped quote/title delimiters, and malformed-definition recovery across small chunk sizes, preventing scanner validity heuristics from drifting away from `swift-markdown` truth.
- Fixed reference-definition prefix harvesting from parser-exposed container paragraph text. The harvester now excludes parser-derived inline source ranges for list items, block quotes, and table cells while preserving valid container definitions that `swift-markdown` omits from the inline model.

Lines such as `\[not a standalone display math opener` now seal as ordinary paragraphs because the boundary scanner only opens bracket display math when `\[` is the entire trimmed line, matching the parser's standalone delimiter rule.
