# Bugfix Log

## Open

- SwiftUI native text selection overlay hang remains unresolved. Current mitigation: keep `MarkdownRendererConfiguration.nativeTextSelection` defaulted to `.disabled` so SiriusMarkdown does not mount SwiftUI's private `SelectionOverlay` path by default. If the hang returns, sample Sirius and look for `GraphHost.flushTransactions` -> `SelectionOverlay.updateNSView` -> AppKit `NSTextField setFont:` / `_invalidateEffectiveFont` / `updateCell`. Source-backed copy affordances, `MarkdownSelectionController`, and observed host/AppKit selection behavior are separate from this explicit SwiftUI overlay switch.

## Fixed

- Mitigated the remaining SwiftUI native text-selection hang path after the first bounding attempt. A fresh Sirius sample on May 13, 2026 showed the same main-thread loop under `GraphHost.flushTransactions` -> private `SelectionOverlay.updateNSView` -> AppKit `NSTextField` font and display invalidation even when native selection was only applied at renderer roots. `MarkdownRendererConfiguration.nativeTextSelection` now defaults to `.disabled`, leaving package copy affordances and `MarkdownSelectionController` available while preserving `.enabled` for explicit host opt-in. The underlying SwiftUI/AppKit overlay behavior remains unresolved and tracked in Open.
- Fixed unbounded SwiftUI native text-selection overlays in the SwiftUI renderer. A Sirius hang sample showed the main thread saturated under `GraphHost.flushTransactions` -> private `SelectionOverlay.updateNSView` -> AppKit `NSTextField` font/intrinsic-size invalidation. The package now keeps Markdown text selectable by default, but applies native selection once at renderer roots instead of per rendered fragment, list item, table cell, and fallback text surface. `MarkdownRendererConfiguration.nativeTextSelection` remains available for explicit host opt-out, and SwiftUI tests now guard against per-block selection modifiers returning.
- Replaced the decorative `swift-markdown` parser call with an AST-to-render-model converter. Block kinds, headings, task list state, ordered-list starts, table cells/alignments, inline runs, code info strings, and HTML blocks now come from `swift-markdown` instead of the earlier line/delimiter classifier.
- Fixed parser identity to satisfy the streaming contract: active-tail IDs stay stable while appending and survive sealing, while deterministic `contentHash` values are stored separately for cache keys.
- Fixed table cell conversion to expose semantic cell text and inline runs instead of raw pipe-padding source text.
- Fixed source slicing and boundary scanning so append-time sealing iterates source lines without materializing the full growing tail string; parser string materialization remains bounded to sealed-region/tail parse boundaries.
- Fixed source line scanning to store chunk slice references instead of allocating per-line byte arrays. Line `String` materialization is now lazy at scanner call sites that explicitly ask for text.
- Fixed inline layout to split `prepare` from cheap width-dependent `layout`. `MeasuredInlineContent` caches segment and unit widths during prepare, so resize/layout passes reuse prepared measurements instead of calling CoreText again.
- Removed the custom SwiftUI inline flow `Layout` that measured each inline fragment with `sizeThatFits`. Inline rendering now builds one policy-gated attributed text payload and leaves wrapping to the platform text system.
- Fixed the SwiftUI renderer to handle structured lists, task lists, tables, code blocks, math blocks, and HTML blocks through block-specific render paths instead of generic `Text(block.text)` fallbacks.
- Fixed renderer configuration to expose protocol hooks for link, image, HTML, code, math, code highlighting, and math rendering.
- Fixed default policy safety by rejecting unknown/file/javascript/data link schemes and blocking image loading by default.
- Fixed CI's Pretext smoke path to run `npm ci` before `npm test`, making the workflow clean-checkout safe.
- Fixed `Tools/pretext-golden/src/index.js` resolving fixtures from `Tools/fixtures` instead of `Tools/pretext-golden/fixtures`.
- Fixed the Pretext golden smoke harness to use the currently published `@chenglou/pretext` package version and provide a Node canvas measurement context.
- Fixed `MarkdownBlockID` churn when a block moved from mutable tail to sealed storage by removing tail/sealed namespace from generated IDs.
- Fixed `MarkdownBoundaryScanner` treating a single trailing newline as a blank-line seal boundary, which split streamed multi-line blockquotes and could seal too early.
- Corrected source-buffer UTF-8 test expectations for Arabic and mixed Unicode byte offsets after expanding byte/line-map coverage.
- Wired parser and inline layout caches into executable code paths with diagnostics counters for tail reparses, sealed-region cache hits/misses, inline prepare, and layout.
- Moved code highlighting, math rendering, and HTML policy evaluation out of `MarkdownBlockView.body` into `MarkdownPreparedBlockContent`, with highlighted-code and rendered-math cache reuse.
- Fixed the public `SiriusMarkdown` product so it now builds an importable umbrella module instead of only composing Core and SwiftUI targets, and added a test that exercises the consumer import surface.
- Fixed active-tail boundary scanning to retain scanner state and scan newly appended complete lines once, preventing long open tails from accumulating O(n²) scan work.
- Fixed active-tail boundary scanning again so incomplete lines already inspected during prior appends are not rescanned until a newline arrives.
- Fixed inline measurement so per-character unit measurement is a cached overwide fallback instead of eager work during normal prepare.
- Fixed renderer preparation so it no longer eagerly stores per-character fallback units for every inline segment.
- Fixed SwiftUI width-dependent inline layout so it can refuse view-time overwide fallback measurement and consume only prepared segment measurements.
- Fixed `BoundedMarkdownCache` to update recency on cache hits instead of behaving like FIFO while claiming LRU-style behavior.
- Fixed the built-in SwiftUI document/streaming views to consume `MarkdownPreparedSnapshot` items, preserve host boundaries, and keep inline policy decisions out of block body evaluation.
- Fixed the default test suite instability caused by AppKit bitmap snapshot rendering under Swift Testing by keeping deterministic headless renderer contract tests in Swift Testing and moving the `MarkdownDocumentView` AppKit pixel check into `Tools/RenderProbe`, a separate release-gated process.
- Fixed diagnostics coverage for render-preparation caches so highlighted-code and rendered-math cache hits/misses are recorded alongside inline cache reuse.
- Fixed the weak Pretext assertion that treated emoji/CJK and RTL drift as an expected passing condition; strict drift now fails the suite instead of being whitelisted.
- Fixed Swift CoreText measurement to match Pretext's selected-font profile for unsupported glyphs by using the selected font's missing-glyph advance instead of silently measuring native fallback fonts.
- Fixed the overwide inline unit fallback cache so Swift Testing no longer crashes while exercising long-word Pretext fixtures.
- Fixed `DocumentReaderDemo` launch crashing in `initializeWithCopy for MarkdownRendererConfiguration` after backend copy-provider changes. Document-style demos now use a source-backed `MarkdownCopyProvider(markdownSource:)` that slices exact UTF-8 source ranges without capturing a full `MarkdownStream` inside renderer configuration; added Unicode slice coverage and verified `swift test`, `Examples/MarkdownDemoApp`, and bundled `DocumentReaderDemo.app` launch.
- Fixed the integration footgun where hosts had to manually keep stream state, renderer configuration, copy providers, caches, and prepared snapshots aligned by adding `MarkdownRenderSession`.
- Fixed the remaining newline-injected prepared-inline view path so SwiftUI now renders the attributed payload natively while prepared line layout is still consumed for width-change counters and tests.
- Fixed inline math coverage by detecting `$...$` as typed math runs without rewriting source and without touching code spans or fenced code.
- Fixed image handling being only visible text by adding prepared image decisions; default behavior remains placeholder-only with no remote loading.
- Fixed selection/copy being purely ad hoc text selection by adding a bounded block-level selection controller with source-backed Markdown and plain-text copy helpers.
- Fixed the Pretext gate being limited to a narrow seed corpus by requiring a 25-group product fixture set with metadata, duplicate name/group rejection, JS mirror parity, and strict Swift-vs-Pretext layout comparison.
- Fixed packaged chat and document presets still requiring callers to opt into prepared-line rendering; `.compactChat` and `.document` now select `.preparedNativeLines`, while raw custom configurations keep `.systemText` as a compatibility fallback.
- Fixed the default code highlighter pretending that unknown diagnostic/log fences were semantically understood by coloring generic strings, numbers, UUID fragments, and timestamps. The default path now normalizes explicit language aliases, highlights supported languages through the embedded Highlight.js backend, and renders plaintext, nohighlight, unlabeled, unsupported, or failed-backend fences plainly.
- Fixed highlighted-code cache identity so repeat render preparation reuses actual highlighted output, while source, normalized language, theme palette, or highlighter identity changes invalidate the cache.
- Fixed a JavaScriptCore-backed highlighter crash path uncovered by Swift Testing crash logs by keeping the backend lazy, locked, and resource-loaded outside static initialization; unsupported platforms and backend failures fall back to plain code.
- Fixed heading typography ownership so H1, H2, and H4-H6 no longer bypass the theme with `.largeTitle`, `.title`, or `.headline` visual/measurement defaults. `MarkdownTheme.headings` now owns H1-H6 visual `Font`, prepared `fontSize`, `lineHeight`, and `fontProfiles`; the old singular heading fields remain deprecated H3 compatibility aliases.
- Fixed prepared native-line redraw during host resizing by measuring the current parent proposal independently of the previously rendered native-line frame, then added a wide-to-narrow AppKit render probe that keeps the SwiftUI view alive while the column shrinks.
- Fixed document and code affordance icon alignment by centralizing SF Symbol rendering in one shared icon view, using `square.on.square`, `square.and.arrow.down.on.square`, and optical chevron offsets across document and code chrome.
- Fixed prepared native-line wrapping for transcript-style paths, commands, URLs, and long identifiers by making visible prepared-line layout containment-first, defaulting overwide fallback on for prepared native lines, preserving preferred path break boundaries in the fallback units, and propagating finite content widths through list markers, quote accents, and table-cell padding.
- Fixed JavaScriptCore environment shim for Mermaid SVG rendering: the bundled `beautiful-mermaid` runtime embeds the ELK layout engine, which resolves its global object from `window`, `global`, or `self`. None of these exist in bare JavaScriptCore, leaving the internal variable `A` undefined and crashing on `A.Math.max(...)`. Added `self`, `window`, `global`, `setTimeout`, `clearTimeout`, and `Error.stackTraceLimit` shims to the production buffer shim script, and relaxed the `Buffer.toString()` signature to match the bundle's zero-argument calling convention.
- Fixed `DefaultMarkdownMermaidRenderer` to produce SVG output in `MarkdownPreparedMermaidDiagram.svg` by loading and caching a separate SVG render function alongside the existing ASCII function during runtime initialization.
- Fixed a JavaScriptCore `EXC_BAD_ACCESS` crash in `JSRopeString::resolveToBuffer` triggered when the `HighlightJavaScriptRuntime` and `MermaidJavaScriptRuntime` ran concurrently during Swift Testing. Both runtimes called `JSGlobalContextCreate(nil)`, placing their contexts in the same default VM group; concurrent JS evaluation from different threads corrupted internal rope-string state. Each runtime now owns an isolated `JSContextGroupRef` created with `JSContextGroupCreate()`, and contexts are created with `JSGlobalContextCreateInGroup` to eliminate cross-runtime VM sharing.
- Fixed Mermaid SVG output rendering as black shapes on dark SwiftUI/AppKit surfaces. The bundled SVG generator emits CSS variables such as `var(--_node-fill)` and AppKit SVG rasterization does not reliably resolve that CSS in the platform image path, so diagrams became black-on-dark and effectively unreadable. The default Mermaid renderer now prepares raster-compatible light and dark SVG variants with concrete colors, stores the dark variant in `MarkdownPreparedMermaidDiagram.darkSVG`, and keeps that work in render preparation rather than SwiftUI `body`.
- Fixed Mermaid diagrams being scaled up to fill the transcript column. `MarkdownBlockView` now renders the prepared platform image at intrinsic SVG size inside horizontal overflow containment, keeping compact diagrams compact while still allowing wide diagrams to scroll.
- Fixed a large SwiftUI integration bug where the first rendered paragraph of a newly selected demo document or stream case could disappear until the window was resized. The visible symptom was that content such as `Wide code should remain inspectable without forcing the entire document surface to grow.` or `Links stay policy-controlled while content streams:` was absent on initial selection even though the underlying `MarkdownSnapshot`, prepared content, and counters were correct.
- Root cause was not Markdown parsing or content corruption. The failure came from SwiftUI subtree reuse across demo case switches combined with stateful prepared-inline rendering. `PreparedInlineTextView` holds width-dependent `@State` such as `containerWidth` and `layoutResult`; when a host reused the same view position at the same width for different prepared content, the old layout could survive until a resize forced recomputation. This made the bug appear renderer-deep even when the final remaining repro was demo-integration-specific.
- Hardened the shared prepared-inline path against that class of stale-state bug. `PreparedInlineTextView` now derives a layout identity from the prepared payload and recomputes prepared native-line layout on `onAppear` and whenever the prepared inline content changes, even if the measured width stays fixed. That keeps fixed-width content swaps from reusing stale line layout until the next resize.
- Fixed `MarkdownDemoApp` case switching by giving the `DocumentSurface` subtree a fresh SwiftUI identity with `.id(example.id)`. Different prepared documents can legitimately begin with the same stable block IDs because block identity is source-range based within a single document/stream, so the demo host must not let SwiftUI treat different selected examples as the same rendered document subtree.
- Fixed `StreamingTranscriptDemo` case switching the same way by keying the rendered `StreamingMarkdownView` subtree with `.id(model.selectedCaseID)`. This addressed the remaining repro in the `Policy Stress` stream where the first streamed paragraph could stay blank until a resize even after the broader shared-inline invalidation fix landed.
- Added regression coverage for the real failure modes, not just synthetic parser/layout checks. New AppKit-hosted SwiftUI tests cover first-layout paragraph visibility, prepared-inline recomputation when content changes at a fixed width, and document-surface height differences when the leading paragraph is present versus absent. These tests exist specifically to catch future regressions where SwiftUI view reuse hides valid prepared content until resize.
- Fixed prepared native-line glyph clipping for transcript-style inline commands. Native line rendering now applies explicit per-run SwiftUI font attributes derived from the measured `MarkdownInlineFontProfiles`, CoreText system-monospaced measurement now matches SwiftUI's system-monospaced rendering intent instead of hard-coding Menlo, and prepared native lines lay out against a font-scaled paint guard so the containment clip does not shear the final glyph. The prepared native-line view also sizes its rendered surface from the offered parent width before overlaying native text, preventing stale wide line frames from polluting later width reads during host resizing. Added screenshot-shaped command regressions for prepared layout, AppKit-hosted rendered line width, width-narrowing relayout reuse, and a rendered bitmap resize check for visible right-edge clipping.
- Fixed package-owned Markdown affordance icons participating in synthesized SF Symbol accessibility text even though their enclosing buttons already provide explicit labels. The shared `MarkdownAffordanceIcon` now marks the decorative symbol image as accessibility-hidden, preserving labels such as "Copy code", "Export document", and "Zoom in diagram" while avoiding extra symbol-description localization work in SwiftUI/AppKit host updates.
- Fixed a post-0.4.7 Sirius hang sample where the main thread was no longer dominated by popup/accessibility symbol localization, but by SwiftUI layout under `GraphHost.runTransaction`, `LayoutChildGeometries`, `StackLayout`, `_FlexFrameLayout`, and `LayoutProxy.dimensions`. The package-side amplifier was the prepared native-line renderer building a `VStack`/`ForEach` subtree with one framed `Text` per prepared line. `NativeInlineLineTextView` now renders one newline-joined attributed payload at the prepared layout height, keeping line breaking owned by `InlineLayoutResult` while collapsing the SwiftUI child tree to a single text surface. `MarkdownMermaidDiagramView` also ignores sub-pixel-identical width preference updates so diagram layout does not feed redundant state writes back into SwiftUI layout.
