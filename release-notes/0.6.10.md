# SiriusMarkdown 0.6.10

SiriusMarkdown 0.6.10 fixes semantic color handling in the native renderer,
including the explicit source-backed document-selection configuration used by
streaming host applications. Native AppKit text selection remains the default
macOS path introduced in 0.6.8 and retained in 0.6.9.

## Fixed

- CoreText-painted prepared lines now carry
  `kCTForegroundColorFromContextAttributeName`, allowing `CTLineDraw` to honor
  the renderer's CGContext fill color instead of falling back to black.
- SwiftUI semantic colors are resolved under the active AppKit appearance or
  UIKit trait collection before native drawing code stores fixed platform or
  Core Graphics values.
- AppKit selectable text and math fallbacks, UIKit CoreText painting, and
  attachment placeholder layers now follow live light/dark appearance changes.
- Appearance changes reuse the same prepared and cached `CTLine` objects; they
  do not parse, prepare, highlight, or rebuild line plans.

## Selection Contract

- Bounded noneditable `NSTextView` leaves remain the default macOS native text
  selection, wrapping, copy, keyboard, and contextual-menu implementation.
- Hosts that explicitly enable source-backed cross-block document selection
  may disable native leaf selection and use the CoreText-painted path without
  losing light/dark text contrast.

## Verification

- 864 Swift tests across 17 suites, including a 320×96 dark-Aqua pixel probe
  matching the affected host configuration and content.
- A 150-block appearance-switch regression preserves every cached CoreText
  line identity and records no parse, prepare, or in-body line-plan rebuild.
- Clean SwiftPM consumer resolution/build, three production demo bundles,
  math and Pretext corpus gates, symbol graphs, and DocC generation.
- UIKit/CoreText compilation validated through the Mac Catalyst target.
