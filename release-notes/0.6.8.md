# SiriusMarkdown 0.6.8

SiriusMarkdown 0.6.8 makes macOS text interaction look and behave like macOS.
Rendered Markdown now uses bounded package-owned AppKit text views for default
selection and secondary-click behavior, without mounting SwiftUI's private
selection overlay.

## Native selection and menus

- AppKit now owns the selection highlight, word/drag/keyboard selection,
  continuous prose wrapping, Copy, and the standard contextual menu.
- Removed the per-block SwiftUI context menu that reduced secondary click to a
  package-only “Copy Markdown” command.
- Exact-source cross-block Markdown selection remains available explicitly and
  uses one document-level context menu. Enabling it disables native leaf
  selection so the two interaction models do not compete.

## Rich inline and streaming behavior

- Image-backed inline math is rendered as a baseline-aligned TextKit attachment
  inside the same selectable paragraph, preserving links, semantic copy, and
  accessibility labels.
- Mixed prepared images and equations retain their order and copy semantic alt
  text/LaTeX rather than TextKit object-replacement characters.
- Selection ranges and the underlying AppKit text view remain stable while a
  streamed tail transitions between text fallback and prepared math imagery.
- Mermaid ASCII and invalid-image math fallbacks use the same selectable native
  leaf. Attachment hosts and caches are pruned when streamed content removes
  them.

## Verification

- 859 Swift tests across 17 suites.
- Full product gate with clean SwiftPM consumer resolution, three production
  demo bundles, the 50-case math corpus, 27 Pretext fixtures, DocC/symbol
  graphs, performance checks, and offscreen AppKit render probes.
- AddressSanitizer coverage for the native AppKit selection suite and attachment
  lifecycle, including image-only semantic copy.
- The selection stress probe observed 12 bounded selectable AppKit text leaves,
  a real inline-math attachment, and no SwiftUI selection overlay.
