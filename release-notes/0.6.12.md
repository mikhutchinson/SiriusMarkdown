# SiriusMarkdown 0.6.12

SiriusMarkdown 0.6.12 fixes a source-backed document-selection beachball in
long generated transcripts. Selection remains enabled and exact-source; the
package now makes its cache-hit path scale independently of document size.

## Fixed

- Prepared inline layout no longer computes a hash by walking every measured
  segment and fallback unit during each width/layout cache lookup.
- SwiftUI prepared-content identity and selection fragment caches no longer
  hash the full natural text, inline runs, font data, and line-range arrays on
  every geometry evaluation.
- Prepared, measured, and laid-out values now carry deterministic two-lane
  fingerprints computed when the values are created or mutated. Hot layout,
  view-identity, and selection cache keys combine those constant-size values.
- Measurement reuse keeps a layout-only fingerprint so metadata-only link or
  source changes do not throw away valid glyph metrics; full rendering and
  selection identities still include that metadata and invalidate correctly.

## Verification

- The captured pre-fix 1,300-line direct cache workload took 353.932 ms for 40
  repeated layout/selection queries. The 0.6.12 release build completes the
  same 40 cache hits in 0.214 ms.
- A genuine AppKit-hosted SwiftUI invalidation test over the same 1,300-line
  block measures a 0.418 ms post-warm median and fails the release build above
  16 ms.
- Mutation-boundary tests cover full versus layout-only prepared identity,
  both fingerprint lanes, supplied measurement geometry, and line-layout
  invalidation. The complete package release gate discovers 873 Swift tests.
