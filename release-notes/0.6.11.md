# SiriusMarkdown 0.6.11

SiriusMarkdown 0.6.11 makes the default macOS AppKit selectable text leaves
cheap and constraint-safe under SwiftUI layout pressure. Native AppKit text
selection remains the default macOS path introduced in 0.6.8; the explicit
source-backed document-selection configuration is unchanged.

## Fixed

- AppKit selectable text leaves no longer rebuild their full attributed
  source, re-enumerate fonts and colors, or re-apply attachments on every
  SwiftUI layout proposal. `configure` short-circuits behind an equatable
  content/environment key, so repeated size negotiation over long nested
  list/quote documents no longer compounds into multi-second main-thread
  stalls in host apps.
- Measured sizes are cached per proposed width and invalidated only when the
  content/environment key changes, so `sizeThatFits` stops re-running TextKit
  layout for repeated identical proposals.
- Attachment host subviews are added, moved, and removed only inside
  `layout()`. `sizeThatFits` can execute inside the window's
  `updateConstraints` traversal, where view-hierarchy mutation re-enters
  AppKit's `_postWindowNeedsUpdateConstraints` guard and is converted into a
  deliberate `EXC_BREAKPOINT` crash; that mutation path is now closed.

## Verification

- New regression test proves stable-content layout passes never rebuild AppKit
  leaf content (`enabledNativeTextSelectionDoesNotRebuildContentPerLayoutPassOnMacOS`).
- New hosted streaming scaling gate proves per-append main-thread cost stays
  bounded as a Core Text painted-line + document-selection document grows
  (`MarkdownStreamingScalingTests`).
- Full package test suite passes (867 tests), including the enabled native
  selection AppKit suite, selection performance tests, and the release
  product gate's serialized AppKit tests.
